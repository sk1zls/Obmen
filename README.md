# Обмен — общая папка в локальной сети

Кроссплатформенный (C++17) сервер обмена файлами для одной локальной сети:
на каждом устройстве запускается программа, выбираются общие папки (их может быть
несколько), и все узлы сети видят одни и те же файлы. Папки сопоставляются
по именам: «Общая» на одном узле синхронизируется с «Общей» на другом,
«Фото» — с «Фото».

Управление — **окно программы с HTML-интерфейсом**: тот же GUI (HTML + CSS + JS),
что отдаёт встроенный HTTP-сервер, показывается прямо в окне через WebView2,
без перехода в браузер. Значок в системном трее позволяет держать программу
свёрнутой. Веб-интерфейс по `http://<ip>:8080/` остаётся доступен с других
устройств и из браузера.

Реализовано три транспорта:

- **TCP** — собственный HTTP/1.1 сервер: GUI и файловое API (скачивание/загрузка).
- **UDP** — автообнаружение устройств (broadcast + multicast), без настройки адресов.
- **FTP** — встроенный FTP-сервер (PASV) для доступа любым FTP-клиентом
  (Проводник Windows, FileZilla, Total Commander, `ftp.exe`).

Плюс автоматическая синхронизация всех папок между узлами с распространением
удалений.

---

## Быстрый старт

```bat
build.bat
build\obmen.exe
```

Открывается окно с интерфейсом программы: слева — сетевые папки, устройства сети
и параметры сервера, справа — файлы и папки, снизу — журнал передач. В трее
появляется значок.

- Кнопка **X** убирает окно в трей — программа продолжает работать.
- Двойной щелчок по значку в трее возвращает окно.
- Правый клик по значку → «Выход» — полное завершение работы.

Если программа не нужна (например, во время игры) — завершите её через меню
трея «Выход»; в фоне она не остаётся. Запуск сразу в трей: `--tray`.

Консольного окна при обычном запуске нет: в оконном режиме консоль скрывается
сразу при старте, поэтому её случайное закрытие не завершает программу. Если
окно открыть не удалось и программа работает как сервер, консоль возвращается;
`--console` оставляет её видимой с самого начала (для диагностики).

Список сетевых папок — в левой колонке окна: «+ Добавить папку» открывает
обозреватель диска, «×» убирает папку из списка (файлы на диске остаются),
щелчок по папке переключает содержимое справа. Так же можно сделать общими
сколько угодно папок — например, «Общая» и «Фото».

При первом запуске общих папок нет и на диске ничего не создаётся — папку нужно
добавить кнопкой «+ Добавить папку» (в списке будет подсказка).

В обозревателе есть быстрый переход: «Рабочий стол», «Документы», «Загрузки»,
«Изображения», «Музыка», «Видео», «Домашняя папка» и «Все диски» — не нужно
идти от корня диска. Там же задаются **имя папки в списке** и **ключ
синхронизации**. Папки синхронизируются, когда совпадают их ключи (регистр не
важен); по умолчанию ключ равен имени, поэтому достаточно назвать папки
одинаково. Если имена разные, ключ задаётся вручную — номером (`1`, `2`, …) или
именем папки соседа: в окне добавления показан список папок, которые раздают
другие устройства, и щелчок по такой папке подставляет её имя как ключ, а своё
имя можно оставить любым. У уже добавленной папки ключ меняется выпадающим
списком рядом с названием («по имени», папка соседа или «другой…» — ввести номер).

Что важно для синхронизации:

- Никаких кнопок «скачать» нажимать не нужно: у папок на обоих ПК должен
  совпадать ключ синхронизации (по умолчанию — имя папки), и содержимое обоих ПК
  само станет одинаковым — в обе стороны, включая удаления.
- Если в левом списке у папки написано «нет пары на других устройствах»,
  значит на соседних узлах нет папки с таким ключом: задайте ключ явно
  (выпадающий список у папки) или добавьте такую же папку на втором ПК.

На втором компьютере той же сети запустите `obmen.exe` (или скопируйте папку
`build`). Через несколько секунд устройства найдут друг друга (UDP), в списке
появится сосед, а файлы начнут синхронизироваться автоматически.

## Сборка

**MSVC (рекомендуется, Windows):**

```bat
build.bat
```

Скрипт находит `vcvars64.bat` (Visual Studio Build Tools 2022/18, Community,
Professional, Enterprise), компилирует ресурсы (`rc.exe`: иконка), подключает
`third_party/webview2` (заголовки + статический лоадер) и собирает
`build\obmen.exe`. Внешних зависимостей нет: лоадер WebView2 слинкован
статически, поэтому `WebView2Loader.dll` рядом с exe не нужен.

**CMake (Windows / Linux):**

```bat
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

На Linux линкуется `pthread`, на Windows — `ws2_32`, `shell32`, `ole32`,
`oleaut32`, `user32`, `gdi32`, `advapi32`, `windowsapp` и
`WebView2LoaderStatic.lib`.
Важно: проект собирается в режиме **C++17** (используется `std::filesystem::path::u8string()`).
Окно и трей есть только на Windows; на других платформах работает режим сервера
с веб-GUI.

**Требование для окна:** компонент «Microsoft Edge WebView2 Runtime». Он есть
на Windows 11 и на большинстве Windows 10 (ставится вместе с Edge). Если его
нет, программа сообщит об этом и откроет интерфейс в браузере — сервер,
синхронизация и FTP продолжат работать.

## Параметры командной строки

```
--root <папка>     первая сетевая папка
--share <имя=путь> ещё одна сетевая папка; можно указывать несколько раз
--name <имя>       имя устройства в сети (по умолчанию имя компьютера)
--port <n>         HTTP-порт GUI и API (по умолчанию 8080)
--ftp-port <n>     FTP-порт (по умолчанию 2121)
--udp-port <n>     UDP-порт обнаружения (по умолчанию 45454)
--interval <сек>   интервал автосинхронизации (по умолчанию 10)
--no-sync          не запускать автосинхронизацию
--no-ftp           не запускать FTP-сервер
--no-ui            не открывать окно (режим сервера)
--tray             запустить свёрнутым в трей, без окна
--browser          дополнительно открыть веб-интерфейс в браузере
--console          не скрывать консоль при запуске окна
--config <файл>    путь к файлу настроек (по умолчанию «Документы\Обмен\obmen.ini»)
--help             справка
```

Настройки сохраняются в `Документы\Обмен\obmen.ini` при изменении списка папок и
переключателей, и восстанавливаются при следующем запуске. Рядом с `obmen.exe`
программа ничего не создаёт: ни настроек, ни папки обмена — общие папки
добавляются вручную в окне. Если старый `obmen.ini` лежал рядом с exe (например,
на рабочем столе), при первом запуске он копируется в «Документы\Обмен».
Папки хранятся строками `share=<имя>|<путь>`; старый формат с одной строкой
`root=<путь>` читается и превращается в папку с именем каталога. Аргументы
командной строки имеют приоритет над файлом.

## Интерфейс

Окно программы — это тот же веб-интерфейс, что и в браузере (страница
`http://127.0.0.1:<порт>/`), показанный через WebView2. Внутри:

- **Сетевые папки** — список папок узла (имя и путь), переключение щелчком,
  «+ Добавить папку» (обозреватель диска с быстрым переходом в «Документы»,
  «Рабочий стол», «Изображения», «Все диски» и т.п., там же имя папки в сети),
  крестик у папки — убрать из списка, «Открыть в проводнике». Если для папки
  нет одноимённой папки на других узлах, под именем написано «нет пары на
  других устройствах». У соседей в списке устройств видны имена их папок.
- **Автосинхронизация** — переключатель и кнопка «Синхронизировать».
- **Устройства сети** — имя, `IP:порт`, статус «в сети/нет», добавление по адресу,
  кнопка «Веб» (открывает GUI соседа в браузере; для синхронизации она не нужна).
- **Файлы** — таблица: имя, размер, дата изменения; переход по папкам, фильтр,
  загрузка drag&drop с прогрессом, скачивание, удаление, создание папки.
  Значки типов файлов — встроенный SVG-спрайт (папка, текст, книга, картинка,
  видео, звук, архив, программа, код), а не символы шрифта.
- **Журнал обмена** — направление, файл, объём, статус, узел.
- **Счётчики** — принято и отдано.
- **Статус-строка синхронизации** (внизу окна) — общая полоса по всем файлам:
  «Синхронизация 62% · файлы: 3 / 7 · 12,4 МБ из 30,0 МБ · осталось 17,6 МБ».
  Пока идёт сверка — «Проверка изменений…», после раунда — «Синхронизировано»
  со временем проверки и объёмом переданного. Неудачные файлы видны там же
  («ошибок: 1»), а пофайловый ход — в журнале обмена.

Меню окна: **Файл** (открыть папку обмена, свернуть в трей, выход), **Сервер**
(синхронизировать, копировать адрес, открыть веб-интерфейс в браузере),
**Справка**. Контекстное меню WebView2 и строка состояния браузера отключены,
чтобы окно выглядело как обычное приложение.

**Трей**: значок с подсказкой (путь к папке). Меню: открыть окно,
синхронизировать, открыть папку обмена, копировать адрес, выход. Двойной
щелчок — вернуть окно. После перезапуска Проводника значок восстанавливается.

## HTTP API

| Метод | Путь | Назначение |
|-------|------|------------|
| GET  | `/` | веб-GUI |
| GET  | `/app.css`, `/app.js` | ресурсы веб-GUI |
| GET  | `/api/status` | состояние узла, пиры, счётчики, прогресс синхронизации (`sync.*`), последние передачи |
| GET  | `/api/shares` | список сетевых папок `{shares:[{name,path,key}]}` |
| POST | `/api/shares` | `{"action":"add","name":"Фото","path":"D:\\Фото","key":"1"}`, `{"action":"setkey","name":"Фото","key":"1"}` или `{"action":"remove","name":"Фото"}` |
| GET  | `/api/files?share=&path=` | содержимое папки |
| GET  | `/api/download?share=&path=` | скачивание файла |
| POST | `/api/upload?share=&path=&name=` | загрузка (сырое тело запроса) |
| POST | `/api/mkdir?share=&path=&name=` | создать папку |
| POST | `/api/delete?share=&path=` | удалить файл или папку |
| GET  | `/api/browse?path=` | обзор диска для выбора папки; `places` — быстрые переходы, `drives=1` — только диски |
| POST | `/api/setroot` | `{"share":"Фото","path":"D:\\Другое"}` — сменить путь папки |
| GET  | `/api/manifest?share=` | манифест `[{p,s,m}]` — для синхронизации |
| GET  | `/api/tombstones?share=` | отметки об удалении `[{p,t}]` |
| POST | `/api/sync` | `{"enabled":true}` / `{"interval":10}` |
| POST | `/api/sync/now` | запустить цикл синхронизации |
| POST | `/api/peers` | `{"addr":"192.168.0.10:8080"}` — добавить узел вручную |
| POST | `/api/transfers/clear` | очистить журнал |
| POST | `/api/openroot` | открыть папку в проводнике (Windows) |

Параметр `share` необязателен: без него используется первая папка из списка
(так работают старые скрипты и прямые ссылки). Вместо `share` можно передать
`key` — ключ синхронизации; тогда узел отвечает своей папкой с этим ключом. Так
и синхронизируются папки с разными именами: по умолчанию ключ равен имени, но
его можно задать номером или именем папки соседа.

Проверки: любой путь нормализуется и приводится к каноническому, выход за пределы
общей папки (`..`, абсолютные пути, диски, `:`) отклоняется с кодом 400.

## FTP

```
ftp://<ip>:2121/
Логин: anonymous (пароль любой)
```

Поддерживаются: `USER`, `PASS`, `SYST`, `FEAT`, `OPTS`, `TYPE`, `PWD/CWD/CDUP`,
`PASV`, `LIST`, `NLST`, `RETR`, `STOR`, `APPE`, `REST`, `SIZE`, `MDTM`, `MKD`,
`RMD`, `DELE`, `NOOP`, `QUIT`. Активный режим (`PORT`) не поддерживается —
используется `PASV`. Загрузки пишутся во временный `.part` и переименовываются
только после успешного завершения.

Верхний уровень FTP — список сетевых папок: `/Общая`, `/Фото`. Внутри папки
пути обычные, например `/Фото/2024/снимок.jpg`. Чтобы подняться из папки
к списку папок, нужно выйти в её корень и выполнить `CDUP` ещё раз.

## Обнаружение устройств

UDP-пакет `OBMEN1|<id>|<имя>|<http-порт>|<ftp-порт>` отправляется каждые 4 секунды
на широковещательный адрес `255.255.255.255`, на направленный broadcast каждой
подсети (`192.168.1.255` и т. п. — по всем адаптерам сразу) и в multicast-группу
`239.255.42.99` на порт `45454` — тоже через каждый интерфейс. Сокет слушает тот
же порт и подписывается на группу на всех адаптерах; пакеты с собственным `id`
игнорируются. Узел считается online, если пакет приходил за последние 15 с.

Доставка в локальной сети бывает **односторонней** — виноваты брандмауэр, режим
изоляции клиентов на точке доступа или несколько сетевых адаптеров. Поэтому одной
рассылки мало:

- услышав соседа, узел отвечает ему unicast (не чаще раза в 4 с): сосед узнаёт
  нас, даже если наши broadcast/multicast пакеты до него не доходят;
- раз в 10 секунд узел представляется соседям по TCP — `POST /api/announce`
  со своими портами. Сосед проверяет представившегося ответным `/api/status`
  (адрес берётся из TCP-соединения) и заводит его как обычный узел. Это работает,
  даже если UDP между узлами не проходит совсем, а TCP проходит.

Если узел всё равно виден только в одну сторону, дело не в программе, а в сети:
сеть на «невидимой» машине должна быть частной (`Get-NetConnectionProfile` →
`NetworkCategory: Private`), `obmen.exe` должен быть разрешён в брандмауэре
Windows, а на точке доступа должна быть выключена изоляция клиентов (AP isolation).

## Синхронизация

Цикл раз в `--interval` секунд (минимум 3), а также по кнопке или при появлении
события (загрузка файла, удаление, обнаружение нового узла). Каждая своя папка
сверяется с папкой пира, у которой тот же ключ синхронизации; если такой папки нет,
она пропускается:

1. Узел забирает у пира `/api/tombstones` и применяет удаления: файлы, удалённые
   на пире, удаляются локально, пустые каталоги подчищаются.
2. Затем забирает `/api/manifest` — список файлов (путь, размер, mtime).
3. Файл скачивается, если его нет локально, или если версия пира новее по
   mtime. Локальная правка никогда не затирается устаревшей копией: при разных
   размерах решает время изменения (при равном времени — id узла, чтобы оба
   узла выбрали одну и ту же версию). Скачивание идёт во временный `.part`,
   затем атомарная замена, после чего файлу выставляется mtime источника — так
   узлы сходятся и не «перекачивают» файл по кругу.
4. Удаление фиксируется в `<общая папка>/.obmen-state.json` («надгробия»)
   и расходится по узлам. Файл, созданный заново после удаления, «воскресает»,
   если его mtime новее отметки об удалении.

Синхронизация двусторонняя: каждый узел тянет недостающее у остальных, поэтому
изменения на любом устройстве попадают на все. Удаления распространяются
благодаря надгробиям. Пустые папки как объекты не синхронизируются — каталоги
создаются по мере появления файлов.

## Структура проекта

```
src/
  main.cpp        точка входа, конфигурация, маршруты HTTP API
  app.h/.cpp      состояние узла, obmen.ini, пиры, журнал передач
  net.h/.cpp      сокеты (Winsock2 / POSIX), таймауты, connect с таймаутом
  http.h/.cpp     HTTP/1.1 сервер (один запрос на соединение) и клиент
  store.h/.cpp    сетевые папки: безопасные пути, листинг, манифест, надгробия
  discovery.h/.cpp UDP-обнаружение: broadcast по всем адаптерам, multicast,
                  unicast-ответ соседу и представление по TCP (/api/announce)
  sync.h/.cpp     движок автосинхронизации
  ftp.h/.cpp      FTP-сервер (PASV)
  json.h          минимальный JSON (разбор и запись)
  gui_assets.cpp  HTML + CSS + JS интерфейса
  ui.h/.cpp       окно приложения: WebView2 с этим же GUI + иконка в трее
third_party/webview2/
  include/        заголовки WebView2 SDK
  x64/            WebView2LoaderStatic.lib (лоадер линкуется статически)
res/
  obmen.rc        ресурсы: иконка приложения
  obmen.ico       иконка (16…256), генерируется tools/make_icon.ps1
test/
  common.ps1       общее для сценариев: пути от репозитория, запуск/остановка узлов,
                   ожидания HTTP и файлов, Assert-True
  run_all.ps1      прогон всех сценариев подряд
  test_ui.ps1      окно+WebView2: страница внутри окна, трей, сворачивание, выход
  test_shares.ps1  несколько папок: API, синхронизация по именам, FTP-корень
  test_http.ps1    API, загрузка/скачивание, имена в UTF-8, защита путей
  test_ftp.ps1     FTP-сессия: LIST, STOR, RETR, SIZE, MDTM, MKD, DELE
  test_sync.ps1    два узла: обнаружение, синхронизация в обе стороны, вложенные папки
```

## Тесты

Тесты — сценарии PowerShell 7 (Windows). Каждый сценарий **сам поднимает свои узлы**
на своих портах, создаёт папки в `test\` и останавливает процессы за собой:
заранее ничего запускать не нужно. Все пути считаются от расположения
репозитория, поэтому тесты работают на любой машине и в любой папке.

```powershell
build.bat                                   # сначала собрать программу
pwsh -NoProfile -File test\run_all.ps1      # все сценарии подряд
pwsh -NoProfile -File test\test_sync.ps1    # или по одному
```

`run_all.ps1` по умолчанию пропускает `test_ui.ps1` (ему нужен рабочий стол);
`-IncludeUi` включает его, `-Filter http` оставляет только совпадающие по имени
сценарии. Каждый сценарий печатает ход проверки и **падает с ненулевым кодом**,
если ожидаемое не выполнилось, — по этому коду и считается итог прогона.

Общее для сценариев — в `test\common.ps1`: путь к `build\obmen.exe` (с понятной
ошибкой, если программа не собрана), запуск и остановка узлов, ожидание HTTP и
файлов, `Assert-True`. Останавливаются только процессы **этой** сборки, так что
запущенное рабочее окно программы тесты не тронут.

Тестовые папки (`test\share1`, `shareA`…`shareD`, `http-share`, `root-share2`
и т. п.), файлы `test\*.ini`, `dl.txt`, `dom-*.html` и логи создаются прогоном
и перечислены в `.gitignore`.

Что проверяет каждый сценарий:

- `test_http.ps1` — API и статика GUI, загрузка/скачивание, имена в UTF-8,
  защита путей, переключатель синхронизации;
- `test_ftp.ps1` — FTP-сессия: LIST, STOR, RETR, SIZE, MDTM, MKD/RMD, DELE,
  коды ошибок;
- `test_sync.ps1` — два узла: обнаружение, синхронизация в обе стороны,
  вложенные папки, манифест и журнал передач;
- `test_delete.ps1` — распространение удалений: файл, папка с вложенным файлом,
  «воскрешение» после повторной загрузки;
- `test_key.ps1` — папки с разными именами и общий ключ синхронизации;
- `test_sync_conflict.ps1` — конфликты: старая копия не затирает свежую правку;
- `test_sync_now.ps1` — кнопка «Синхронизировать» выкладывает все папки узла;
- `test_big.ps1` — файл 20 МБ, целостность SHA-256, параллельные загрузки;
- `test_root.ps1` — смена пути папки через API и запись в `obmen.ini`;
- `test_shares.ps1` — несколько папок: API, синхронизация по именам, FTP-корень,
  разметка списка папок (headless Edge);
- `test_places.ps1` — окно «Добавить папку»: быстрый переход и имя папки в сети
  (headless Edge + CDP);
- `test_ui.ps1` — окно внутри exe: `ObmenMainWindow`, окна Chromium, страница
  `http://127.0.0.1:<порт>/` через отладчик WebView2, сворачивание в трей по
  крестику, возврат окна и выход с кодом 0 (нужен рабочий стол).

## Ограничения и безопасность

- Программа рассчитана на **доверенную локальную сеть**: аутентификации нет,
  любой, кто дошёл до порта, получает доступ к папке. Не выставляйте порты в
  интернет; при необходимости ограничьте доступ правилами брандмауэра.
- По умолчанию брандмауэр Windows спросит разрешение для `obmen.exe` —
  разрешите доступ для частных сетей.
- `POST /api/announce` (представление узла по TCP) не доверяет телу запроса:
  адрес берётся из самого TCP-соединения и проверяется ответным `/api/status`,
  поэтому подделанное представление не создаёт узел в списке.
- Разрешаются только пути внутри выбранной папки; символические ссылки,
  ведущие наружу, отсекаются канонизацией пути.
- `STOR`/загрузка через HTTP пишут `.part` и переименовывают по завершении;
  прерванная передача не портит существующий файл.
- Передача одного файла не докачивается по `Range`; для FTP поддержан `REST`
  для `RETR`.
- Одновременное изменение одного и того же файла на двух узлах разрешается по
  mtime: побеждает более новый; содержимое не сливается.
- TLS не поддерживается (ни HTTPS, ни FTPS) — трафик в сети открытый.
- Окно требует WebView2 Runtime (есть на Windows 10/11); без него интерфейс
  открывается в браузере. Окно и трей — только Windows.
